# 连接官方选手端和真实图传

这里记录的是我们实际调通的方式：一台电脑运行学生版赛事引擎，另一台电脑同时运行官方选手端和 BNGUClient。官方选手端版本为 `12.0.0.213 Student`，使用 RMUC 模式。

## 默认地址填什么

| 设置 | 本机官方程序转发时填写 |
| --- | --- |
| IP 地址 | `127.0.0.1` |
| 服务器地址 | `mqtt://127.0.0.1:3333` |
| MQTT 端口 | `3333` |
| 机器人编号（Client ID） | 实际机器人编号；我们测试的红方3号为 `3` |
| 用户名 | 本次测试留空 |
| UDP 监听端口 | `3334` |
| 编码类型 | 自动检测，或 H.265 |

`127.0.0.1` 表示这台电脑自己。`3333` 和 `3334` 才是端口号：前者收发状态和控制消息，后者接收视频。

这套连接里，赛事引擎即使在另一台电脑上，自定义客户端仍连接本机官方程序。因此，不要把赛事引擎的 IP 直接填到自定义客户端中。

## 接线和启动顺序

1. 启动赛事引擎，让官方选手端、裁判系统主控按官方步骤接入测试网络。
2. 把图传接收端通过 USB 接到运行客户端的电脑。只给机器人主控上电还不够。
3. 按官方包的 `ReadMe.txt` 安装运行环境和图传驱动。我们遇到过 USB 已插上、Windows 却没有驱动的情况。
4. 从官方包根目录运行 `Start.bat`。它会启动选手端及配套后台；不要只单独打开其中一个 exe。
5. 在官方选手端确认机器人登录成功、状态有数据，并能显示摄像头画面。所测版本通过 P 键打开设置，不是启动时弹出机器人选择页。
6. 停止本机模拟测试服务，避免它与官方程序占用同一个数据端口。
7. 打开 BNGUClient，按 Esc → 操作中心 → 连接配置 → 网络，按上表填写。
8. 点击服务器地址右边的“连接”，确认“已接收”消息数增加。
9. 到“机器人”页选实际显示对象，例如红方3号步兵；到“视频源”页选 UDP，点“应用并连接”。

Client ID 决定连接哪台机器人；机器人下拉框决定屏幕上查看谁。两处都要核对。修改 Client ID 后需断开并重新连接。

在这套已验证的连接方式下，先保持官方选手端和配套后台运行。我们还没有单独验证“关闭官方界面、只保留部分后台”是否可用。

## 连不上时怎么查

| 现象 | 先检查什么 |
| --- | --- |
| 官方选手端也没有机器人状态 | 先检查赛事引擎、主控联网和官方登录 |
| 官方有状态，自定义客户端连接失败 | 地址是否为 `127.0.0.1:3333`、Client ID 是否对应已登录机器人、是否有其他程序用了同一身份 |
| 官方也没有图传画面 | 接收端 USB 是否接好、图传驱动是否安装、收发两端是否正常连接 |
| 自定义客户端一直等待首帧，接收量为 0 | MQTT 是否连接、Client ID 是否正确、视频来源 IP 和接收端口是否正确 |
| 视频接收量增加，但输出一直为 0 | 查看启动终端的解码错误，记录第一条错误和前后几行 |
| 有画面但明显落后 | 对比官方画面，记录是否逐渐越积越慢；不要用 FPS 直接当成延迟 |

程序已修复一处导致首帧无法输出的问题，也移除了正常显示路径中较慢的一次图片转换。本地分段测试通过；优化后的实机总延迟和清晰度仍需继续对比，没有把它写成已完成的现场验收。

## 官方文档中的地址为什么不同

[官方通信协议资料页](https://bbs.robomaster.com/wiki/20204847/811363)提供各版本文件。我们核对的 V1.3.0 中：

- 正文第 42 页“自定义客户端协议”：服务器为 `192.168.12.1:3333`，自定义客户端为 `192.168.12.2`，视频监听 UDP `3334`。
- 第 81 页附录示例代码：`MyMqttClient` 的默认 IP 是 `127.0.0.1`，默认端口为 `3333`。

正文的接入地址、示例代码的默认值和本机实际运行方式要分开看。这里采用本机地址，是因为我们在本机官方程序上实际收到过真实状态和图传，不是认定所有赛场都固定使用这个地址。其他协议版本和现场配置需按对应文件核对。

## 服务运行在另一台电脑时

这时 `127.0.0.1` 仍指向自己，不能用来找另一台电脑。需要填写对方提供服务的实际 IP，并让视频发送端把画面发到运行 BNGUClient 的电脑。当前 IP 输入框同时用于数据连接和视频来源筛选；如果两个来源不同，需要分别核对，不能把赛事引擎地址当作所有接口的地址。
